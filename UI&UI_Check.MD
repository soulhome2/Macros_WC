# UX/UI-аудит закладки «Макрокоманды»

**Продукт:** ИнтеллектХ · веб-конфигуратор ITV · вкладка «Макрокоманды»
**Объект аудита:** `prototypes/index.html` (самодостаточный прототип, RU/EN, light/dark)
**Пользователь:** инженер, интегратор, администратор; десктоп, многочасовые сессии, повторяющиеся действия
**Метод:** эвристики Нильсена, Material 3 (иерархия, состояния, плотность), WCAG 2.1 AA (+2.5.8 из 2.2)
**Дата:** 23.09.2026

Контрасты измерены расчётом по формуле WCAG для токенов ONE PSIM обеих тем — значения в [приложении](#приложение-измеренные-контрасты).

---

## Резюме

Прототип хорошо решает главную проблему исходного экрана: правило читается как рецепт, а не как граф, каскадный выбор объектов масштабируется на серверные каталоги, состояния «не сохранено / неполное» видны. Основные риски сместились в три зоны: **необратимые действия** (два разных «Удалить», нет защиты от закрытия вкладки), **скорость повторной работы** (нет переупорядочивания действий, правка параметров только через модальное окно) и **доступность неактивных элементов** (выключенные кнопки не объясняют причину и не проходят по контрасту).

### Топ-3 приоритетных правки

| # | Правка | Блок | Эффект | Оценка |
|---|--------|------|--------|--------|
| 1 | **Переупорядочивание действий** — drag-handle + `Alt+↑/↓` + пункт «Переместить» в меню узла | UX-логика, D3 | Сейчас порядок реакций меняется только удалением и пересозданием узла: это ядро задачи конфигуратора | M |
| 2 | **Развести деструктив и защитить данные** — «Удалить узел» / «Удалить макрокоманду» с разными подписями и местами, `beforeunload`, тост «Отменить» после удаления | Визуальная иерархия + UX, VH2/U1/U3 | Две одинаковые красные кнопки «Удалить» в одном экране и отсутствие защиты при закрытии вкладки = реальная потеря часа работы | S |
| 3 | **Вернуть быструю правку параметров в правую панель** — параметры выбранного узла inline, модалка только для создания | Плотность, D1 | Правка таймаута или архива стоит 4 клика вместо 1; при многочасовой работе это основная рутина | M |

## 1. Визуальная иерархия

| Проблема | Критичность | Почему это проблема | Рекомендация |
|---|---|---|---|
| **VH1.** В шапке пять кнопок почти одного веса: «Копировать», «Изменить», «Удалить», «Отмена», «Сохранить» | med | Первичное действие не считывается за один взгляд; красный деструктив стоит в 2 см от «Сохранить» — классическая ошибка соседства (Нильсен №5) | Три группы: слева работа с макрокомандой (копировать, удалить — в overflow «⋯»), по центру правка узла, справа «Отмена / Сохранить». Между группами разделитель 16 px |
| **VH2.** Два разных «Удалить» с одинаковым лейблом: вверху — удаление узла, внизу слева — удаление всей макрокоманды | **high** | Одинаковая подпись + одинаковый красный стиль при разной зоне поражения; пользователь ориентируется на подпись, а не на положение | «Удалить узел» (иконка узла) и «Удалить макрокоманду» (иконка корзины). Разный вес: узел — tertiary, макрокоманда — danger-outline |
| **VH3.** Заголовки панелей «Условие запуска» / «Действия» набраны overline 11 px uppercase | med | Самый важный смысловой каркас средней панели оформлен самым тихим стилем; взгляд первым цепляет синюю подсветку выделенного узла | Заголовок панели — `body-md-medium` 14 px, обычный регистр, с иконкой типа; overline оставить для секций правой панели |
| **VH4.** Выделение узла — только фоновая заливка `accent-soft`, рамка обнуляется | low | Единственный канал — цвет (1.4.1); на плотной схеме выделение теряется при прокрутке | Оставить заливку + левый индикатор 3 px `--one-selected-indicator` + сохранить рамку |
| **VH5.** «ИЛИ» между условиями и «Добавить условие» — одинаково тихие 11 px | low | Логический оператор (смысл) и действие (команда) имеют равный вес | «ИЛИ» — chip с рамкой; «Добавить условие» — tertiary-кнопка с иконкой |

## 2. Плотность и когнитивная нагрузка

| Проблема | Критичность | Почему это проблема | Рекомендация |
|---|---|---|---|
| **D1.** Параметры узла (архив, приоритет, таймаут, текст оповещения) редактируются только в модальном окне; правая панель при этом содержит 2 контрола и текст | **high** | Модалка перекрывает схему и требует «открыть → изменить → применить» на каждую мелкую правку; для 8-часовой смены это основная рутина. Правая панель недогружена, хотя место есть | Гибрид: правая панель — контекстные параметры выделенного узла (без каскада), модалка — только «Добавить» и смена типа/объектов. Либо non-modal side sheet поверх инспектора |
| **D2.** Нет массовых и повторных операций: мультивыбор макрокоманд, дублирование реакции, копирование условия между правилами | med | Типовой сценарий интегратора — «то же самое ещё для 10 дверей»; сейчас каждый раз полный проход каскада | Чекбоксы в списке + «Дублировать» на узле + «Вставить из буфера» для условия/реакции |
| **D3.** Порядок действий нельзя изменить: только добавить и удалить | **high** | Порядок реакций = логика правила. Ошибка в порядке требует пересоздания узлов со всеми параметрами | Drag-handle на узле, `Alt+↑/↓` с клавиатуры, «Переместить выше/ниже» в контекстном меню |
| **D4.** Список слева без сортировки, группировки и поиска по объекту | med | «Какие макрокоманды используют камеру 17» — частый вопрос при пусконаладке; сейчас только поиск по имени и сводке | Фильтр «по объекту» (тот же каскад), сортировка по имени/типу/изменению, группировка по типу |
| **D5.** Между каждой парой узлов свой «+» | low | На сценарии из 10 действий — 11 одинаковых целей, ни одна не приоритетна | Сохранить «+» при наведении на промежуток; постоянную кнопку «Добавить реакцию» вынести в шапку панели «Действия» |

|---|---|---|---|

| **U6.** В модальном окне правки нет привязки к узлу: заголовок «Изменить реакцию» без имени | low | При возврате из окна к схеме теряется контекст, особенно в ветках Wait | Подзаголовок: «Действие 3 из 5 · ветка „Событие произошло“» |

## 8. Доступность

| Проблема | Критичность | Почему это проблема | Рекомендация |
|---|---|---|---|
| **A1.** Тултип открывается только по наведению мыши, не закрывается по `Esc` | **high** | 1.4.13 «Content on Hover or Focus»: контент должен вызываться фокусом, скрываться по `Esc` и быть наводимым (последнее выполнено) | Открывать по `focus`, закрывать по `Esc`, элемент-триггер сделать фокусируемым (`tabindex="0"`, `aria-describedby`) |
| **A2.** Список макрокоманд: `role="listbox"` + кнопки `role="option"`, но без навигации стрелками | med | Смешанный паттерн: скринридер обещает listbox, а клавиатура ведёт себя как набор кнопок; Tab проходит по всем строкам | Либо честный listbox (`tabindex` roving, стрелки, Home/End), либо `role="list"` со ссылками |
| **A3.** Каждая кнопка «+» между узлами — отдельный таб-стоп | med | На правиле из 10 действий до правой панели больше 20 остановок | «+» показывать при наведении/фокусе узла и убирать из таб-порядка (`tabindex="-1"`), добавлять действие с клавиатуры через меню узла |
| **A4.** Нет `h1` и ссылки «Перейти к содержимому» | low | Навигация по заголовкам начинается с `h2`, структура страницы неполная | `h1` — «Макрокоманды» (визуально скрытый), skip-link к средней панели |
| **A5.** Смена языка и темы не переносит фокус и не объявляется | low | После переключения фокус уходит в начало документа | Сохранять фокус на контроле, объявлять через `role="status"` |

## Примеры «было → стало»

### 1. Неактивные кнопки не объясняют причину (S1 + C2)

**Было** — причина в `title`, но `pointer-events:none` не даёт подсказке появиться, а текст кнопки имеет контраст 2.22:1:

```html
<button class="btn btn-outline" data-act="editNode" disabled
        title="У цикла нет события-триггера: интервал задаётся в инспекторе">Изменить</button>
```
```css
.btn:disabled{ background:var(--one-control-disabled); color:var(--one-fg-disabled); pointer-events:none }
```

**Стало** — кнопка остаётся «живой» для указателя и скринридера, причина видна и наведением, и рядом с кнопкой:

```html
<button class="btn btn-outline" data-act="editNode" aria-disabled="true"
        aria-describedby="why-edit">Изменить</button>
<span id="why-edit" class="helper">У цикла нет события-триггера — интервал задаётся в настройках</span>
```
```css
.btn[aria-disabled="true"]{ background:var(--one-control-disabled); color:#8A8B92; cursor:not-allowed } /* 3.1:1 */
.btn[aria-disabled="true"]:hover{ background:var(--one-control-disabled) }
```
```js
if (t.getAttribute("aria-disabled") === "true") return;   // клик игнорируется в обработчике
```

### 2. Два одинаковых «Удалить» (VH2)

**Было** — в одном экране две красные кнопки с одинаковой подписью и разной зоной поражения:

```
Шапка:        [Копировать] [Изменить] [🗑 Удалить] [Отмена] [Сохранить]     ← удаляет узел
Левая панель: [+ Добавить]                         [🗑 Удалить]              ← удаляет макрокоманду
```

**Стало** — разные подписи, разный вес, деструктив макрокоманды убран из основного ряда:

```
Шапка:        [Изменить узел] [Удалить узел]  │  [Вернуть сохранённое] [Сохранить]  [⋯]
                                                                                      └ Копировать
                                                                                        Удалить макрокоманду…
Левая панель: [+ Добавить макрокоманду]
```

Подтверждение удаления узла дополняется тостом «Узел удалён · Отменить» (8 с), удаление макрокоманды остаётся модальным с вводом-подтверждением при наличии зависимостей.

### 3. Порядок действий (D3)

**Было** — реакция создаётся только в конкретной точке вставки, порядок потом не меняется:

```
+ ── [Камера · Инициировать тревогу]
+ ── [СКУД · Заблокировать дверь]
+ ── [Оповещение · Отправить e-mail]
```

**Стало** — узел можно перетащить, переместить с клавиатуры и продублировать:

```
⠿ [1] Камера · Инициировать тревогу            [⋯]
⠿ [2] СКУД · Заблокировать дверь               [⋯] ← Alt+↑ / Alt+↓ перемещают
⠿ [3] Оповещение · Отправить e-mail            [⋯]   меню: Дублировать · Переместить · Удалить
```

```js
function moveAct(id, dir){                      // dir: -1 вверх, +1 вниз
  const list = listOf(id);                      // список ветки, где лежит узел
  const i = list.findIndex(a => a.id === id);
  const j = i + dir;
  if (i < 0 || j < 0 || j >= list.length) return;
  remember();
  [list[i], list[j]] = [list[j], list[i]];
  S.dirty = snap() !== S.saved[cur().id];
  render();
}
```
