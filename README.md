# Макрокоманды / Macros — прототип для WEB-конфигуратора

Проработка экрана **«Макрокоманды»** для веб-конфигуратора ITV (Интеллект X · Axxon One).
Это первая сводная версия: не копия толстого клиента и не повтор первого веб-графа,
а редактор, в котором правило читается как рецепт, а параметры открываются кликом по узлу.

**Исходная задача.** Был скриншот первичного веб-варианта (узлы на свободном холсте,
каталог реакций справа) и полный домен толстого клиента на вкладке «Программирование».
На скриншоте клик по «Условие запуска» ничего не делал — инспектора не было.
Свободная расстановка узлов и «Обновить позиции» для двух карточек не помогали.
Часть домена десктопа (режим, меню раскладки, цикл, Wait-ветки, расписание) на макете отсутствовала.

## Быстрый старт

Откройте **[prototypes/index.html](prototypes/index.html)** двойным кликом — сеть и сборка не нужны.
Файл содержит правки по итогам UX/UI-аудита; сам аудит и статус по каждой находке — в [UI&UI_Check.MD](UI&UI_Check.MD).
В шапке: язык (**Русский / English**) и тема (светлая / тёмная). Данные демонстрационные,
изменения живут до перезагрузки; тема и язык запоминаются в `localStorage`.

## Что умеет прототип

**Список**
- Сверху комбобокс «Тип макрокоманды» (Все / События / Авто / Цикл), под ним один поиск по всем типам.
- Бейджи типа (палитра, не статус), режима, «в меню», «неполное».
- Режим «Никогда» визуально приглушён. Неполная макрокоманда выделена и ведёт к добавлению реакции.
- Внизу панели крупные «Добавить» (выбор типа новой макрокоманды) и «Удалить» — для выделенной макрокоманды, с подтверждением.
- При создании события или авто сразу открывается окно «Задать условие запуска» — как «+» для реакции.
- Копировать; несохранённые правки не теряются при смене строки без диалога.

**Рецепт вместо холста**
- Авто-раскладка сверху вниз. Мини-карта и ручные координаты узлов не нужны.
- Сводка словами: «Когда … — сделать …».
- Две панели: «Условие запуска» и «Действия». Переключатель вида в шапке: условие сверху или слева — выбор запоминается.
- Каждое условие запуска — отдельный узел, несколько соединяются через **ИЛИ**; под ними кнопка «Добавить условие».
- «+» между узлами открывает тот же каскад для реакции: тип объекта → объект → реакция, с фильтром по набору.
- Сверху «Изменить» и «Удалить» работают с выделенным узлом — триггером или реакцией — и открывают своё окно подтверждения или правки. У цикла триггера нет, кнопки выключены с подсказкой.
- Wait for event / Wait till previous — две колонки веток.

**Окна правки узла**
- Условие запуска и реакции задаются каскадом с поиском: тип объекта → объекты → событие или реакция. Типы как с сервера; набор на клавиатуре фильтрует список.
- Там же блок «Параметры»: архив, приоритет тревоги, таймаут, текст оповещения, реле и прочее — всё, что уникально для узла.
- Объекты выбираются списком с галочками: клик добавляет или снимает, список остаётся открытым. Чипы с крестиком снимают объект, открывает список только кнопка «Выбрать объекты…».
- Множественный выбор и для условия (источники события, пустой список = любой объект типа), и для реакции (действие выполнится для каждого выбранного объекта; пусто = объект, инициировавший запуск).
- Ожидаемые события ветки Wait for event — такие же узлы схемы со своим «Добавить условие».

**Правая панель: настройки и информация**
- Вверху «Дополнительные настройки» макрокоманды: режим Никогда / Всегда / временная зона, «Добавить в меню раскладки», интервал цикла и «случайно».
- Ниже «Сопутствующая информация»: сводка словами на отдельном поле, где событие, объекты и реакции выделены цветом текста (палитра подобрана под светлую и тёмную тему), баннеры о несохранённых правках, пустой макрокоманде и режиме, подсказки по типу правила.
- Наведение на сводку раскрывает тултип со всей макрокомандой: настройки (тип, режим, временная зона, интервал цикла, меню раскладки) → условие запуска с полными списками объектов → пронумерованные действия с объектами и параметрами. Прокрутка при большом содержимом, скрывается через секунду после ухода курсора; наведение на само окно отменяет закрытие.
- Узлы схемы тоже подсказывают полный список объектов, спрятанный за «и ещё N».

**Оболочка**
- Та же шапка конфигуратора, что у закладки «Расписания»: текущая вкладка — Макрокоманды.
- Полная локализация RU / EN, Light / Dark на токенах ONE PSIM. Разделители панелей — как у расписаний.
- Демо-данные тоже двуязычные: имена макрокоманд, объекты, события, реакции и тексты оповещений. Переименование и правка текста пишутся в слот текущего языка (`name` / `nameEn`, `message` / `messageEn`).
- Ctrl+S сохранить, Ctrl+Z / Ctrl+Y отменить и повторить, Esc закрыть диалог.

## Чем отличается от скриншота и от десктопа

| | Первый веб-граф | Толстый клиент | Этот прототип |
|---|---|---|---|
| Редактор | Свободный холст | Вложенный список аккордеонов | Рецепт с авто-раскладкой |
| Параметры узла | Клик не работал | Поля под заголовком блока | Правая колонка — инспектор выбранного узла |
| Каталог реакций | Постоянно справа | Кнопка «добавить» в списке | Появляется по «+», не занимает инспектор |
| Поиск и фильтр типов | Нет | Два/три отдельных списка | Один список + сегмент |
| Wait-ветки | Не показаны | Вложенные действия | Две колонки |
| Сводка словами | Нет | Нет | Есть |
| Автоправила | Строка в списке без детектора | Создаются на детекторе, видны в Programming | Событие + много объектов-источников, событие можно сменить |

## Модель данных

```js
{
  id, type: "event" | "auto" | "cycle",
  name, mode: "never" | "always" | "schedule", scheduleId?,
  heartbeat?, random?, inMenu,
  detectorId?,                                 // не используется: источники в conditions.devices
  conditions: [{ id, event, devices[], threshold?, value?, trend? }],
  actions: [Action]
}

Action = {
  id, kind, params,
  then?, else?,                                // wait-event / wait-previous
  waitEvents?                                  // фильтр для wait-event
}
```

Условия запуска в продукте — дизъюнкция. AND между условиями прототип **не добавляет**.

## Фикстуры

1. Авто: движение на нескольких детекторах периметра → запись в архив.
2. Событие: дым → тревога + голосовое оповещение.
3. СКУД: отказ в доступе на нескольких считывателях → тревога, блокировка двери, e-mail.
4. ОПС: пожар на нескольких зонах/извещателях → тревога, запись, голос, разблокировка аварийного выхода, оповещатель.
5. Событие: потеря связи → ждать 30 с восстановление → иначе тревога.
6. Цикл: каждые 8 ч случайно → проверка записи + предупреждение о наложении.
7. Ручная: режим «Никогда», в меню раскладки, без условий.
8. Неполная: есть условие, нет действий.
9. По расписанию: «Вне рабочих часов» → снять холл с охраны.

## Принятые решения

- Три колонки как у расписаний: список · рецепт · инспектор. Каталог не держим открытым всегда.
- Тип макрокоманды задаётся при создании и списком слева, отдельный выпадающий «Тип» на карточке не нужен.
- Автоправила на этой закладке задаются так же, как событийные: событие + набор объектов-источников. Привязка к одному детектору при создании снята.
- Каталог реакций и событий — представительный, с СКУД и ОПС, не полный перечень продукта.
- Цвета типов — палитра (teal / purple / magenta), статусы «неполное» и предупреждения — feedback-тройки ONE PSIM.
- Самодостаточный HTML: токены и лестницы контролов из ONE.PSIM.PrototypeKit встроены в файл, без CDN и без `bridge.css`.

**Сознательно не добавлено**

- AND между условиями запуска (на десктопе его нет).
- Объекты другого домена сверх камер, детекторов, СКУД и ОПС.
- Исполнение макрокоманды и живой API.
- Полный каталог всех детекторов и всех параметров каждого действия.
- Ручное размещение узлов, мини-карта, «Обновить позиции».
